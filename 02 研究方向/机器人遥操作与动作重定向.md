# 机器人遥操作与动作重定向

核心问题：人的手和身体提供操作意图，怎样把它转换为**目标机器人实际能够执行、可以记录并用于训练**的动作。实时遥操作、离线视频重定向和仿真动作生成分别列出，避免把好看的重建视频当作已验证控制系统

关联：[[02 研究方向/机器人数据采集与数据质量]] · [[02 研究方向/机器人数据与遥操作技术路线对比]] · [[02 研究方向/DH116机器人数据与遥操作研究方案]] · [[02 研究方向/从人类视频学习灵巧操作_近期论文对比]]

## 三个不同层次

1. **采集层**：普通 RGB／RGB-D、XR 手追踪、主从控制器或动捕手套，输出人的关键点、手腕位姿或主臂关节
2. **映射层**：坐标对齐、手型比例、受限逆运动学、关节平滑和碰撞处理，输出目标本体动作
3. **执行与数据层**：控制器真正发出命令，反馈实际状态，按时间记录图像、动作和模式；后续策略才学习这组数据

这里的**闭环**可能由人观察视频后修正，也可能由机器人策略自己根据传感器修正。**双向遥操作**还要求机器人接触力等信息回到人的触觉／力觉通道；有相机画面不等于双向力反馈。[[03 论文卡片/08_数据与遥操作/Forward and Reverse Teleoperation for Dexterous Manipulation and Human Intervention|P148 · DITTO-X]] 是比较力／触觉接管的现有入口

## 为什么不能直接复制人的关节角

人的五指结构、拇指对掌、骨长、关节轴和独立自由度与机器人不同。同样的角度可能让机器人指尖到不了物体，也可能让耦合关节互相冲突

[[03 论文卡片/08_数据与遥操作/DexPilot - Vision Based Teleoperation of Dexterous Robotic Hand-Arm System|P198 · DexPilot]]、[[03 论文卡片/08_数据与遥操作/AnyTeleop - A General Vision-Based Dexterous Robot Arm-Hand Teleoperation System|P196 · AnyTeleop]] 优化手指向量或指尖关系，并约束机器人关节；[[03 论文卡片/08_数据与遥操作/Dexterous Imitation Made Easy - A Learning-Based Framework for Efficient Dexterous Manipulation|P199 · DIME]] 学习映射；[[03 论文卡片/08_数据与遥操作/SPIDER - Scalable Physics-Informed Dexterous Retargeting|P209 · SPIDER]] 再加入物理接触。三类方法分别需要明确对应、训练分布或可模拟场景，不存在由“手部 21 点”自动得到任何机器人的安全控制命令的通用保证

对 DH116，需先建立**主动轴到各关节的映射及耦合关系**，再计算指尖目标误差。人手 21 点是观察表示，不应写成要给机器人发送 21 个关节命令。左右手侧别、符号、零位与尺度必须独立核验

## 系统流程：从观察到可训练轨迹

相机／头显／控制器 → 原始采样时间戳 → 追踪与置信度 → 初始姿态／坐标系对齐 → 受限手指重定向＋手腕到机械臂映射 → 平滑、动作边界与碰撞检查 → 控制目标与执行反馈分开记录 → 按 episode 保存 → 质量审计 → 策略训练与独立测试

这条链是综合阅读得到的接口划分，不表示每篇论文都实现全部模块。各论文对标定、滤波、力反馈和保存格式的实际覆盖见主卡，缺失指标保持“未报告”

## 频率与延迟要分开记

- [[03 论文卡片/08_数据与遥操作/AnyTeleop - A General Vision-Based Dexterous Robot Arm-Hand Teleoperation System|P196 · AnyTeleop]] 的感知／重定向设计频率与运动生成目标频率不同，不能写成统一端到端频率
- [[03 论文卡片/08_数据与遥操作/Holo-Dex - Teaching Dexterity with Immersive Mixed Reality|P197 · Holo-Dex]] 的手追踪、重定向、PD 控制和存储频率分别记录；高频控制并不意味着示范按同样频率保存
- [[03 论文卡片/08_数据与遥操作/Universal Manipulation Interface - In-The-Wild Robot Teaching Without In-The-Wild Robots|P193 · UMI]] 在部署接口显式处理推理延迟与动作时序匹配；这属于训练—部署对齐，不能只删掉延迟帧来替代
- [[03 论文卡片/08_数据与遥操作/SPIDER - Scalable Physics-Informed Dexterous Retargeting|P209 · SPIDER]] 的 FPS 是生成轨迹的吞吐，不是机器人实时响应速度
- [[03 论文卡片/08_数据与遥操作/Closing the Loop in Teleoperation - Episode-Level Data Quality Assessment and Feedback for High-Quality Demonstration Collection|P208 · DQAF]] 的回合后反馈等待也不是控制延迟

本项目至少区分：采样时间、主机接收时间、追踪输出时间、命令发送时间、反馈观测时间。若没有可靠共同时间基准，不声称已测得端到端延迟

## 双臂和多指怎样扩展

[[03 论文卡片/08_数据与遥操作/Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware|P191 · ALOHA / ACT]]、[[03 论文卡片/08_数据与遥操作/Open-TeleVision - Teleoperation with Immersive Active Visual Feedback|P194 · Open-TeleVision]]、[[03 论文卡片/08_数据与遥操作/ACE - A Cross-platform and visual-Exoskeletons System for Low-Cost Dexterous Teleoperation|P195 · ACE]] 是同步双臂输入的代表；[[03 论文卡片/03_双臂协作/Mobile ALOHA - Learning Bimanual Mobile Manipulation Using Low-Cost Whole-Body Teleoperation|P072 · Mobile ALOHA]] 加入移动底盘；[[03 论文卡片/03_双臂协作/DemoBot - Efficient Learning of Bimanual Manipulation with Dexterous Hands From Third-Person Human Videos|P190 · DemoBot]] 的双臂长程任务主要在仿真中评估。两侧独立追踪不能解决接触时的相对坐标、交接角色和两臂碰撞

建议先保留公共时钟、左右侧别、共享物体坐标和任务阶段，再研究角色切换。先从仿真中同一物体的稳定—操作角色对比开始，避免在未验收单手控制时直接规划双臂硬件演示

## 适合普通实验室的阅读顺序

先读 [[03 论文卡片/08_数据与遥操作/AnyTeleop - A General Vision-Based Dexterous Robot Arm-Hand Teleoperation System|P196 · AnyTeleop]] 理解模块划分与受限重定向，再读 [[03 论文卡片/08_数据与遥操作/Dexterous Imitation Made Easy - A Learning-Based Framework for Efficient Dexterous Manipulation|P199 · DIME]] 的纯 RGB 入口；通过 [[03 论文卡片/08_数据与遥操作/DexPilot - Vision Based Teleoperation of Dexterous Robotic Hand-Arm System|P198 · DexPilot]] 理解多视角和捏合接触，再比较 [[03 论文卡片/08_数据与遥操作/OPEN TEACH - A Versatile Teleoperation System for Robotic Manipulation|P151 · OPEN TEACH]]／[[03 论文卡片/08_数据与遥操作/Holo-Dex - Teaching Dexterity with Immersive Mixed Reality|P197 · Holo-Dex]]／[[03 论文卡片/08_数据与遥操作/Open-TeleVision - Teleoperation with Immersive Active Visual Feedback|P194 · Open-TeleVision]] 的 XR 反馈

需要离开固定机械臂采集时，阅读 [[03 论文卡片/08_数据与遥操作/Universal Manipulation Interface - In-The-Wild Robot Teaching Without In-The-Wild Robots|P193 · UMI]]、[[03 论文卡片/08_数据与遥操作/DexCap - Scalable and Portable Mocap Data Collection System for Dexterous Manipulation|P009 · DexCap]]、[[03 论文卡片/04_灵巧操作/DexUMI - Using Human Hand as the Universal Manipulation Interface for Dexterous Manipulation|P086 · DexUMI]]；重视臂控制稳定时阅读 [[03 论文卡片/08_数据与遥操作/GELLO - A General, Low-Cost, and Intuitive Teleoperation Framework for Robot Manipulators|P192 · GELLO]]、[[03 论文卡片/08_数据与遥操作/ACE - A Cross-platform and visual-Exoskeletons System for Low-Cost Dexterous Teleoperation|P195 · ACE]]；最后读 [[03 论文卡片/08_数据与遥操作/SPIDER - Scalable Physics-Informed Dexterous Retargeting|P209 · SPIDER]] 和 [[03 论文卡片/08_数据与遥操作/TUCO - Curating Simulation Demonstrations for Sim-to-Real Robot Policy Co-Training|P207 · TUCO]]，把映射结果的物理可行性与下游数据价值连起来
