## 详细摘要

### 1. 研究背景

双臂面对多项任务时既要满足先后依赖、拿取物体的连续性，又要利用可以并行的时间段；串行任务计划浪费双臂能力。（全文 §1）

### 2. 论文要解决的问题

给定自然语言多任务指令和环境状态，如何同时完成跨任务分解、去冗余、左右臂显式分配和无死锁并行调度。（§1、§3）

### 3. 之前方法存在的问题

直接生成线性步骤的 LLM 规划器不显式约束依赖、占臂和物体持有关系；即便动作正确，也常退化为顺序执行或产出物理冲突计划。（§1–2）

### 4. 核心思路

先让 LLM 生成并纠正全局依赖 DAG，再以规则化图重遍历分配左右臂、合并重复动作、插入同步并解除持有冲突。（§3，图 2）

### 5. 方法与系统结构

RAG 检索程序知识，LLM 把任务包合并为节点带动作类型、所需臂数、持续时间和前驱边的 DAG；校验节点依赖与资源约束。调度器仅在前驱完成、对应臂空闲时启动，pick-use-place 要保持同臂；双臂节点同步等待两臂。若两臂各持物导致后继双臂动作死锁，则回滚较晚的 pick 及依赖子树并重新排队。这是集中式高层规划，底层 ACT/DP/π0 可分别执行技能，并非端到端 VLA 或两个自主智能体的学习框架。（§3、图 2、式 4–8）

### 6. 输入信息

多任务自然语言指令、场景物体和机器人状态、记忆检索结果、技能库与动作约束，以及执行历史反馈。（§3，图 2）

### 7. 输出 / 动作表示

输出左右臂随时间的动作计划与高层操作节点，节点表示 pick、place、use 等离散技能及依赖；它不直接预测关节/末端连续动作。双臂动作需同一时刻分配两臂，单臂动作可交叉并行。（§3）

### 8. 数据来源与采集方式

自建 X-DAPT，涵盖厨房、办公室、温室、工厂等 10 场景，超过 1000 个任务包，按 easy/medium/hard 设置任务复杂度；它是规划评测集，论文没有报告用 X-DAPT 生成大量低层动作训练轨迹。（§4）

### 9. 数据处理与数据增强

跨任务节点合并消除重复操作，例如一次持刀完成多次切割再放刀；DAG 校正去除错误依赖，并在调度时加入臂占用与死锁约束。未报告面向图像或动作训练的常规数据增强。（§3、§5.3）

### 10. 训练方式

高层采用 GPT-4o 或 DeepSeek V3 推理加规则调度，非训练新 VLA；底层实验使用 ACT、DP、π0 等已训练技能策略。论文未把高层规划描述为联合训练双臂策略。（§5.1）

### 11. Benchmark 与实验设置

X-DAPT 四个重点场景和三档任务复杂度，评估 TEI（执行效率）、TFR（任务失败率）、PPR（跨包并行）、APR（双臂同时使用）。基线为 LLM3、ChatGPT-Prompts、VOYAGER、Embodied TaPA、LLM-Planner、FLTRNN、RoCo；另测试 DeepSeek V3、RoboTwin 和真机。（§5、表 1–3、附录 E）

### 12. 真机实验

在 Franka Research 3、UR5e 与人形机器人配置中验证任务计划；温室场景的 Franka 任务给出 RoboPARA 相比顺序基线更短的 10 步执行序列，论文图 1 报真机执行时间缩短约 30%–50%。这些是规划与技能执行验证，不能视为开放世界连续控制通用成功率。（§5、图 1、4、附录 E）

### 13. 主要实验结果

GPT-4o 厨房场景 TEI 1.407、TFR 0、APR 0.334；办公室 TEI 1.553、APR 0.293，多数基线 PPR 为 0（表 1）。不同难度下 RoboPARA 的 APR 为 0.342/0.321/0.351；Hard 的 TEI 0.869、TFR 0.041（表 2）。论文文字报告可比任务包执行步骤约减少 7%。（§5.3）

### 14. 消融实验

去掉环境信息、指令约束、deadlock check、DAG correction 分别造成规划质量下降；例如厨房 Hard 包完整模型 TFR 为 0，去掉 deadlock check 为 0.618、去掉 DAG correction 为 0.488，说明资源检查和图校正不能省。（表 3）

### 15. Failure Case

LLM 生成错误依赖、臂持物冲突和死锁是被显式检测的规划失败；论文展示任务执行失败后闭环重规划，但复杂包中仍可能超过有限轮纠正能力。VOYAGER 在该设定下无法给出具体双臂执行步骤。（§3、§5.3–5.5）

### 16. 主要局限

作者说明使用 API 的成本高，DAG 反复校正使 token 消耗平均为基线约 1.3 倍；复杂依赖仍可能纠正失败，技能库绑定既定场景和任务模板，未见任务泛化受限。（§5.5）

### 17. 与已有工作的关系

相较顺序式 LLM Planner 或对话式 RoCo，核心改进是显式 DAG 依赖、跨包重组和资源约束下的并行调度；π0 等只是可接入的底层技能执行器。（§2–5）

### 18. 对当前研究方向的价值

给普通夹爪双臂长期任务提供“检测执行冲突→重规划”的高层架构参考；若用于 VLA 错误恢复，需补充连续动作失误、感知误判与技能失败的因果诊断，现有规划器并未解决这些低层问题。（§3、§5）

### 19. 一句话总结

RoboPARA 以经校正的任务 DAG 和资源约束调度，让两只机械臂在多任务中安全并行与重新组合动作。
