## 论文简介

一个通用大模型能根据图像反复发动作、在仿真里取得高成功率，是否就意味着它能长期可靠地控制实体机器人？这份报告把“在给定信息和充足尝试下做成任务的具身能力”，与“成本、时间和物理后果都可接受的实用具身智能”分开研究。作者不只比较模型回答，还让它实际闭环控制多个仿真环境，并分析外部执行框架怎样改变结果

输入包括任务指令、机器人图像与状态，以及测试前从训练示范整理的知识包。知识包不只是几句提示，还可包含动作轨迹、接触图像、运动学工具、阶段检查和恢复程序。测试前冻结包与 GPT 权重，每回合独立开始；模型调用工具提出动作，执行后再看新观察、判断是否继续或修改。部分消融还让任务微调的 π0.5 先提出动作，再由 GPT 审核，所以报告中的“GPT 冻结”并不表示系统从未训练任何模型

主要证据覆盖十二个评测设置及八种真机配置。扩大动作预算能显著改善可纠正的失败，例如 RoboDojo 的一组 210 回合实验从 1× 截止的 27.62% 提高至同回合扩展的 81.90%；但不能拿它直接减去另一组 Harness 消融的 54.17%，两者模型协作、采样与汇总口径不同。真机暴露更明显的限制：插头在三种平台合计 0/11，长时间推理期间物体状态可能变化，过热、碰撞停机和洒出的液体也不能靠继续增加步骤解决

因此，报告的启发不是让更大的模型替代全部控制，而是把任务选择、可靠动作执行和物理结果核验接起来。对机械臂、DH116 与 D435i，可先在仿真比较固定技能、视觉反馈和不同审核频率，再研究接触是否真实成立及已完成步骤是否被破坏。RoboRSI 提供部分公开运行框架与知识包，但不是八种真机的完整复现包；其后来发布的 27B 模型确实涉及权重训练，独立技术报告仍未发布，必须与本报告保持文献边界

## A. 基本信息与研究问题

### 1. 报告究竟检验了什么

Embodied Competence（具身能力）在本文主要指模型利用机器人感知、动作接口和环境反馈完成具身任务的能力。Practical Embodied Intelligence（实用具身智能）进一步要求能在现实约束中可靠、有效率地运行。两者不是论文建立了统一阈值的数学指标，而是用来解释实验证据的概念区分

报告的问题包括：通用模型固定权重时能做到多少；成功来自模型还是外部 Harness（连接模型、上下文、工具、执行与反馈的框架）；多给动作次数改善多少；这些优势是否能迁移到实体硬件；下一代评测应怎样计入推理时间和物理副作用

它没有证明模型理解了全部物理规律，也没有在统一成本下赢过所有机器人策略。跨基准动作、传感、分母和预算不同，十二个百分比不能简单平均成“通用具身智商”

### 2. 十二个设置与“五类机器人”的含义

桌面操作：RoboDojo、RoboLab、LIBERO-PRO、LIBERO-Long++、LIBERO-Ultra-Long；灵巧操作：Bench2Dex、DexJoCo；人形移动操作：SIMPLE；长程家庭活动：BEHAVIOR；导航：VLN-CE R2R、VLN-CE RxR、LHPR-VLN。这里 LIBERO 的不同协议和两套导航数据各计一个设置，不是十二种独立机器人本体（§2.1）

## B. 相关工作与区别

[[03 论文卡片/01_VLA/Do As I Can, Not As I Say - Grounding Language in Robotic Affordances|SayCan]] 用语言提出高层技能，再用可执行性选择；Inner Monologue 把成功检测和场景反馈送回规划；Code as Policies 生成调用感知与控制接口的程序。它们说明高层语义与低层执行可以分工，不能由语言计划正确就推出动作正确

VLA（视觉—语言—动作模型）把图像和语言映射为机器人动作，通常经过机器人示范训练。[[03 论文卡片/01_VLA/OpenVLA - An Open-Source Vision-Language-Action Model|OpenVLA]]、[[03 论文卡片/01_VLA/π0.5 - a Vision-Language-Action Model with Open-World Generalization|π0.5]] 提供不同开放与泛化路线。ACT（动作分块 Transformer）与 Diffusion Policy（以扩散模型生成动作序列）改善动作多模态与连续执行，但也需要相应数据、观察和动作接口。本文不以一张结果表否定这些训练路线，而研究通用推理器和训练过的控制器怎样协作（附录 B）

记忆、恢复和世界模型解决的层次不同：[[03 论文卡片/01_VLA/MEM - Multi-Scale Embodied Memory for Vision Language Action Models|MEM]] 帮助策略使用历史；[[03 论文卡片/07_泛化与长程任务/Recova - Agent-Guided Failure Recovery for Autonomous Robotic Manipulation|Recova]] 专门研究恢复；[[03 论文卡片/06_扩散模型_流匹配_IL_RL/BeyondMimic - From Motion Tracking to Versatile Humanoid Control via Guided Diffusion|BeyondMimic]] 学习全身技能并在推理时引导运动。这些互链是本库的层次比较，不声称本报告以 BeyondMimic 为实验底层

## C. 核心贡献、协议与方法流程

### 1. 训练示范 → 准备知识包，而非偷看测试答案

ICL（In-Context Learning，上下文学习）是通过当前上下文、文件和工具利用经验，通常不更改模型权重。作者允许模型先研究训练示范，因为传统策略也会使用这些示范训练；但这是一种给定训练信息的评测协议，不能写成无示范零样本能力

模型分析训练数据 → 整理任务知识包 K → 记录并冻结其内容 → 测试回合以只读方式读取。包可有六类内容（图 2–3）：任务阶段与顺序、数值运动／抓取参考、图像与接触裁剪、正逆运动学和检索代码、完成检查与恢复办法、机器人接口及来源元数据。结构由准备过程形成，不是作者规定每个任务都必须有同样六份文件

冻结的原因是阻断测试回合间经验传播与针对测试结果改包：每回合重新建立会话，保留本回合历史但不向另一个测试回合写回新经验；GPT 权重和 K 均不变。测试初始状态、隐藏对象位姿、接触和评估器信息是否能看，必须按各基准协议分别核对，不能把某个环境允许的 RGB-D 或校准信息推广给所有实验

### 2. 同回合延长动作预算，不等于重置十次

1× 是该基准标准动作步数，10× 是至多十倍动作步数，不是十倍 token、十倍现实时间，也不是成功重置后挑最好的一次。主文原则是在同一环境后果与历史下继续，成功、终局失败或预算耗尽后结束，失败造成的洒液或掉落不会被抹去

附录实施有差别：Bench2Dex 对标准超时回合用原始动作精确重放恢复边界，再延续原上下文；DexJoCo 的新模型会话接续同一个仍在运行的仿真及原历史；导航附录描述为对初始失败继续扩展评测并保留先前成功或较好指标，不能简单把它等同所有操作实验的逐步重放。BEHAVIOR 不做 10×，因为标准时限本来就长

尤其要区分表 2 的“独立 1× 运行”与“10× 运行在 1× 时的截断”：上下文知道预算不同，会改变策略，因此有些结果并不相同。必须在同一列和同一协议内比较

### 3. Harness 不是只有提示词

一个闭环可以写为：指令＋当前观测 → 读取知识与阶段 → 选择动作工具／技能 → 构造候选动作 → 检查动作与目标是否匹配 → 执行 → 新图像与机器人状态 → 检查接触、支撑、位置或阶段条件 → 继续、改策略或终止

正向运动学 FK 把关节角转换成末端姿态，逆向运动学 IK 从末端目标求关节命令。它们让高层模型以更直观的空间目标推理，而不必心算所有关节。动作审核与执行后的状态检查不同：前者可阻止错误提议，后者才知道现实是否真的做成；两者都不能仅凭“模型说已完成”代替物理结果

知识包提供示范参考和可运行帮助程序；执行轨迹与日志保留本回合历史和来源；恢复模块把“抓空、滑落、遮挡、阶段停滞”等症状对应到调整动作。不过，本报告对这些组件的作用有的只是回顾性案例，没有逐项因果消融，不能把所有收益都分配给某一模块

### 4. System 2 与 System 1 的实际协作

System 2（慢速高层推理器）是 GPT-6-Astra；System 1（低层学习策略）在 RoboDojo 消融中是 **在 RoboDojo 上微调过的 π0.5**。以下三种设置不同（§3.1、图 7）：

1. 仅 VLA：观察与目标交给 π0.5，直接执行它的动作
2. 开环协作：GPT 给子目标，VLA 生成关节动作后直接执行，GPT 不逐次审核候选轨迹
3. 闭环协作：VLA 提案 → FK 转成可供 GPT 理解的末端运动 → GPT 接受、修改或拒绝 → 再执行与反馈；L 是每次审核的动作数量

GPT 冻结仅针对推理器，不抹去 π0.5 的预训练和任务微调。另有若干主实验禁用 VLA，直接让 GPT 通过末端或关节接口控制，不能把所有十二个结果都归为“GPT＋π0.5”

在真实 G1 上还出现 System 0（已有高频运动控制器）：GPT 调用手臂目标、手部开合和厂商速度接口，由现成控制器执行，未直接控制腿部关节，也没有证明 GPT 在高频连续输出全身平衡动作

### 5. 动作表示与动作块

末端绝对位姿、相对方向移动、关节角目标对模型而言不是等价接口。动作块表示一次推理后执行多步，可减少调用次数，却也减少中途反馈。固定 L=4 可能把错误连续执行四次；自适应 L∈{1,2,3,4} 则由模型按阶段选择。闭环 VLA 审核的 L 与直接控制动作块的 L 含义略有不同，图 7、表 13 分开记录

## E. 不足、RoboRSI关系与未来方向

### 1. 作者用真实案例指出的局限

**物理状态核验**：Hang mugs中头相机看到杯柄与挂钩重叠，却没验证钩穿过杯柄；模型后来把手指闭合当作抓到，杯子实际在桌上。拼图看似组成矩形，细微缝隙未满足，后续“修正”反把拼图拆开。可见重叠、口头报告与真正接触／支撑不能等价（图6）

**不可逆后果**：杯子早早翻倒洒液，再扶起继续倒也无法收回洒出的液体；Assembly插销落地超出可达范围，有预算也不能继续。Fold Glasses的成功恢复来自改成侧面接近并试提，而非机械重复同一动作

**破坏已有进度**：耳机本已挂好，再调耳罩把头带拉下；工具箱盖没持续保持开启，后续装入受阻。不能把已完成子目标永久打勾，需要在后续动作后检查关键不变量

**真机时间、示范和机械代价**：专家写上下文或采集示范都花人力；碰桌保护停止、PiPER关节碰撞错误、手部堵转和62°C温度阈值终止都不能用仿真加步数解决。温度数值是该次平台记录，不能照搬为DH116允许温度

**泛化局限**：知识包依赖任务覆盖，Open组、没有示范的RoboLab和无示范家庭原型都更难；真实示范需要相同机器人与观察动作约定，不能视为免费资源

### 2. 下一代评测原型不是成熟排行榜

作者提出按人类需求定义任务、不给域内示范、推理时世界继续运行。在 Isaac Sim 公寓原型中，机器人搬水果却让冰箱从300秒开到765秒；水龙头没关且排水口关闭，水持续溢出；等模型决定关炉火时鸡蛋已经烧焦。若只检查最后位置或“曾经熟了”，会漏掉这些过程错误（§5、图10–12）

这是少量定性案例与设计主张，未发布一个由这些片段推导出的统一成功率。判分器还需能识别接触、温度与副作用，仿真保真与服务延迟也会影响评测。图10中的时间、温度等常数为示例规格，不是通用安全规范

### 3. RoboRSI究竟与报告是什么关系

RSI（Recursive Self-Improvement，递归自我改进）在框架层可表示：保存执行证据 → 找到失败 → 改上下文组织、工具、检查与恢复逻辑 → 在固定条件复测 → 保留改善版本。这里可以始终冻结基础模型权重。报告使用的冻结知识包评测则要求测试回合间不改包，不能把离线框架迭代混进其测试协议

RoboRSI-27B-Preview是另一个后续模型发布：官方模型卡说明从Qwen3.8-27B进一步后训练，用交互经验形成监督并改变权重。它与“固定GPT＋改Harness”不同，也不是把闭源GPT权重开放了。模型卡宣称RoboCasa成功26.0→46.5%、输出token59.5K→15.9K；这些属于项目模型发布结果，不是本报告v2表格，采样等细节应待独立技术报告核实

### 4. 本库分析与我们的下一步设想

报告支持“目标选择—低层执行—反馈核验”的分工，却没有证明任何低层技能库都能即插即用。真机样本小、部分为展示、上下文与预算不一致；精细接触与长期可靠性证据仍弱。独立冻结测试与未来部署累积经验也不矛盾，只是回答不同问题，实验中应分开记分

结合机械臂＋普通夹爪／DH116＋D435i，可先在仿真建立固定可验证技能：接近、预抓、闭合、试提、稳定保持、放回；高层只选技能及参数，低层按限位与驱动约束执行。D435i负责物体位置和可见性，结合关节／电流等可得反馈验证接触；没有传感证据就标“未知”，不能把模型自信当夹持成立

比较基线可设为固定程序、无反馈高层、每阶段反馈、高风险阶段才审核四种条件，在相同初始状态与动作预算下记录整回合成功、物理状态误判、破坏既有进度、恢复次数与墙钟时间。另设冻结知识包测试与跨回合经验更新测试，避免污染评测。这是未来研究方案，**尚未在我们的硬件完成**

与BeyondMimic的互补点是低层可复用运动先验与高层执行审核；不能把人形运动直接当DH116抓取策略，也不能把扩散训练时筛除不稳定轨迹称为部署任务失败恢复。统一专题与优先阅读路线见 [[02 研究方向/全身运动技能与具身执行框架]]
